Web Services

A document-oriented implementation of SOA

Web Services are a document-style implementation of an SOA architecture involving the following elements:

  • A message exchange protocol, typically SOAP.
  • A standard, interoperable message container, typically XML.
  • A standard language to define the service contract, typically WSDL.

In practice this translates to a request, generally sent over HTTP POST, though other transports such as JMS or SMTP are possible. HTTP has become the de-facto standard. The message body is usually XML, though other formats like JSON are also used. An intermediate registry called UDDI can be used to store all available web services and their WSDLs, so a consumer can discover which service satisfies its needs and the contract conditions in the WSDL. UDDI has evolved in practice into API Managers with extra features such as security, versioning and quotas.

Typically, then:

WS = SOAP + XML + WSDL + UDDI

In the Java world, since Java 6 there is a standard specification for web services called JAX-WS along with its reference implementation. Additional products provide extra features on top of JAX-WS, notably Apache Axis and Apache CXF.

WSDL

WSDL is the language used to define a web service exposing a coarse-grained business capability that encapsulates several operations, entirely built on XML. It describes a public interface: the operations that can be requested from the service and the data they take. Data types are typically defined through XSD and the request protocol is usually SOAP.

There are two patterns for calling a service:

  • RPC: the message contains an element with the method name to invoke followed by parameters and values. On arrival the request is directly mapped to the corresponding class and returns a value. It has two flavours: encoded, highly coupled — if the interface changes you must change this too, and it's the most correct way to implement polymorphism — and literal, where no interface checks are performed and parameters and values are sent literally.
  • Document: no wrapping element for the method exists as in the previous case; message parts appear directly inside the body. There are also two flavours: Literal, where the message exactly matches the existing schema, and Literal Wrapped, where an additional tag indicates the operation being invoked and then the rest of the message follows.
<definitions name="StockQuote"
    targetNamespace="http://example.com/stockquote.wsdl"
    xmlns:tns="http://example.com/stockquote.wsdl"
    xmlns:xsd1="http://example.com/stockquote.xsd"
    xmlns:soap="http://schemas.xmlsoap.org/wsdl/soap/"
    xmlns="http://schemas.xmlsoap.org/wsdl/">

    <types>
       <schema targetNamespace="http://example.com/stockquote.xsd"
              xmlns="http://www.w3.org/2000/10/XMLSchema">
           <element name="TradePriceRequest">
              <complexType>
                  <all>
                      <element name="tickerSymbol" type="string"/>
                  </all>
              </complexType>
           </element>
           <element name="TradePrice">
              <complexType>
                  <all>
                      <element name="price" type="float"/>
                  </all>
              </complexType>
           </element>
       </schema>
    </types>

    <message name="GetLastTradePriceInput">
        <part name="body" element="xsd1:TradePriceRequest"/>
    </message>

    <message name="GetLastTradePriceOutput">
        <part name="body" element="xsd1:TradePrice"/>
    </message>

    <portType name="StockQuotePortType">
        <operation name="GetLastTradePrice">
           <input message="tns:GetLastTradePriceInput"/>
           <output message="tns:GetLastTradePriceOutput"/>
        </operation>
    </portType>

    <binding name="StockQuoteSoapBinding" type="tns:StockQuotePortType">
        <soap:binding style="document" transport="http://schemas.xmlsoap.org/soap/http"/>
        <operation name="GetLastTradePrice">
           <soap:operation soapAction="http://example.com/GetLastTradePrice"/>
           <input>
               <soap:body use="literal"/>
           </input>
           <output>
               <soap:body use="literal"/>
           </output>
        </operation>
    </binding>

    <service name="StockQuoteService">
        <documentation>My first service</documentation>
        <port name="StockQuotePort" binding="tns:StockQuoteSoapBinding">
           <soap:address location="http://example.com/stockquote"/>
        </port>
    </service>

 </definitions>

SOAP

SOAP is a communication protocol used to invoke web services and receive a response by exchanging files. A SOAP message is made up of:

  • Envelope: always the first element of the message.
  • Header: carries information about how the message must be processed.
  • Body: the actual payload. In an RPC-style WSDL it contains the details of the method being called; in a document-style WSDL it contains the message directly.
