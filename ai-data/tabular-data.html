Tabular Data

El terreno real de trabajo para la mayoria de problemas de analytics y machine learning

La mayoria de proyectos reales en negocio y salud arrancan en tablas: filas, columnas, timestamps, categorias, mediciones y missing values. Aqui se decide gran parte de la calidad del modelo final mucho antes de entrenarlo.

1. Problem framing

Antes de tocar los datos intento fijar la unidad de analisis, la variable objetivo, la decision que el modelo debe soportar y la metrica que realmente importa. Un buen baseline evita mucho trabajo inutil despues.

2. Data preparation

El trabajo tabular consiste en gran parte en joins, filters, aggregations, reshaping y control cuidadoso de missing values. Categorical variables, duplicados, identificadores inconsistentes y leakage pueden romper un modelo antes incluso de elegir algoritmo.

3. Feature engineering

Muchas mejoras fuertes vienen de mejores features: ventanas temporales, resumenes agrupados, ratios, flags, variables derivadas del dominio y codificaciones mas informativas para categorical data. Aqui es donde el contexto de negocio o salud se vuelve decisivo.

4. Disciplina de evaluacion

Prefiero pensar en train, validation y test antes que en resultados optimistas de una sola tirada. En tabular data tambien es clave preguntarse si el split respeta el tiempo, las entidades y el contexto real de operacion.

5. Tooling que uso o estudio aqui

  • R data frames como estructura base de analisis.
  • dplyr y tidyr para Data Wrangling y reshaping.
  • ggplot2 para exploratory analysis y deteccion de errores.
  • SQL, JDBC, ODBC y FHIR cuando los datos viven en sistemas externos.
  • GLM, tree-based models y otros metodos supervisados una vez que la tabla es fiable.
